# What an API key is

An API key is a long string of letters and numbers that proves to a provider that a request is coming from you. When a tool uses your key, the provider sees your account, applies your limits, and bills you. The key is the thing that links the tool's activity to your account.

## A simple way to picture it

A key is like a personal access pass to a service. When a tool presents your pass, the service lets it in as you and records the usage on your account. Anyone holding the pass can act as you on that one service, which is exactly why a key has to be kept private. It is not a password you log in with; it is a token that tools use on your behalf in the background.

## What a key is not

A key is not your account login, and it is not your identity everywhere. It usually works for one provider only. A key for one service does nothing on another. Most providers also let you create more than one key and cancel any of them, so a key is replaceable. If a key is ever exposed, you can cancel that key and make a new one without losing your account.

## Why it is long and random

The key is long and random so that nobody can guess it. That randomness is its security. It also means there is no way to recover a key by remembering it; if you lose it, you make a new one. This is normal and expected, and it is why you should copy a key somewhere safe the moment you create it.

## The one rule that matters

A key is private. Treat it like a card number: paste it only into the tool that needs it, never share it in a message or a public place, and never put it where others can see it. Almost every BYOK problem traces back to a key ending up somewhere it should not have. Keep the key private and most of the risk disappears.
